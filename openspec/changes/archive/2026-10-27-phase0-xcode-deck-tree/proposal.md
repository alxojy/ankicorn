# Proposal

## Why

The bridge builds and its C ABI is tested in Rust, but nothing in iOS has called it yet. Phase 0 is only done when the app runs in the simulator and prints the deck tree from rslib. This change adds the Xcode project, the typed Swift layer over the bridge, and that first on-screen proof, so every later feature builds on a verified Swift-to-engine path.

## What Changes

- Add `app/Cornhub.xcodeproj` (generated by XcodeGen from a committed `app/project.yml`; both are committed so the gate's `verify` can find the project) with the app, unit-test and UI-test targets and a `Cornhub` scheme. iOS 26 minimum, Swift 6, bundle id `com.alxojy.cornhub`, display name Cornhub.
- Link `build/RslibBridge.xcframework` and `swift-protobuf` (Swift Package Manager).
- Generate Swift protobuf types from `third_party/anki/proto/anki/*.proto` into `app/Cornhub/Backend/Generated/` (committed).
- Generate a service/method index table from rslib's own generated dispatch code, with a drift test.
- Add the Swift `Backend` layer: lifecycle, a generic protobuf call, `BackendError` mapping, and wrappers for exactly `open_collection`, `close_collection`, `add_deck` and `deck_tree`.
- Add a Phase 0 diagnostic screen that shows the deck tree returned by rslib, and a launch argument that seeds a few sample decks.
- Add `scripts/bootstrap.sh` (engine, XCFramework if missing, protobuf generation, XcodeGen).
- Unit tests and a simulator UI test with a screenshot.

Out of scope: Theme and Ink styling, the real Decks screen, the review flow, importing `.apkg`, sync, any wrapper beyond the four methods above.

## Capabilities

### New Capabilities
- `backend-client`: the Swift API over the bridge: service/method indices, generic call, error mapping, and the first typed wrappers.
- `app-shell`: the app target builds for iOS 26, launches in the simulator, opens a collection through the engine and shows its deck tree.

## Impact

- PLAN.md: Phase 0 ("Done when: the app runs in the simulator, opens a sample collection, and prints the deck tree from rslib"). No parity-table rows are touched.
- New: `app/`, `scripts/bootstrap.sh`, `scripts/gen-swift-protos.sh`, `scripts/gen-service-index.mjs`. No changes to protected files.
- Tools: XcodeGen and `protoc-gen-swift` (both installed via Homebrew). SwiftLint is optional and not required.
- The simulator test must run serially on one existing simulator (`iPhone 17`) because the dev machine has 8 GB of RAM.
